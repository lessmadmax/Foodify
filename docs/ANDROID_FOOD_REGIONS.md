# Android 음식 영역 보정과 분석 단계 관리

2026-10-30 마무리. 기존 촬영 화면에서 선택한 사진의 영역을 보정하는 흐름이다.

## 사용 흐름

1. 사진 촬영 또는 갤러리에서 선택한다.
2. 사진 아래의 '사진 N 음식 영역 보정'을 누른다.
3. 음식 테두리의 꼭짓점을 순서대로 누르고 '영역 완성'을 선택한다.
4. 여러 음식은 각각 별도 영역으로 지정한다. 마지막 점 취소·영역 삭제로 수정한다.
5. '보정 적용'으로 촬영 화면에 돌아온다. 다시 열면 같은 사진에 적용한 영역이 복원된다.
6. '자동 저장하고 분석'을 실행하면 업로드 대기 정보와 서버 식단의 capture_info에 경계가 저장된다.

보정은 선택 기능이다. 현재 중량 산출은 기존 사진·AR 요약 기반 분석을 사용한다.
실제 AR 부피 계산에 적용하려면 원본 깊이·접시 기준면·밀도와의 연결 및 실측 검증이 이어져야 한다.
업로드 전 보정값은 촬영 화면에 유지되고, 업로드 대기 파일 생성 이후 앱 재시작·재전송에서도 함께 보존된다.
업로드 전 촬영 화면을 완전히 종료한 상태의 보정 자동 복구는 후속 작업이다.

## 자동 분할 연동 범위

- Flutter와 Android 사이에 foodify/segmentation 채널을 추가했다.
- prepare: 앱 내부 사진의 크기·SHA256·좌표계·자동 분할 가능 여부를 반환한다.
- segment: 동일 사진 지문을 포함한 영역 결과를 주고받도록 Flutter 측 검증과 오류 처리를 구현했다.
- 현재 Android는 automaticAvailable=false, segment는 MODEL_NOT_READY로 응답한다.
- MobileSAM은 PC 실행까지 검증한 상태다. Android 모델 변환·실행기 구현과 S23 성능 검증이 다음 단계다.
- 자동 경계가 준비되면 컨트롤러는 추출 단계를 거쳐 보정 화면에 결과를 전달한다. 현재는 수동 경계 보정 화면으로 연결된다.
- 현재 편집 계약은 다각형 목록이다. PC의 PNG 마스크 및 내부 구멍을 Android에 연결할 때 래스터 마스크 편집·좌표 변환을 확장하고 경계 손실을 평가해야 한다.

## 단계와 실패 복구

사진 준비 → 자동 경계 추출(지원 시) → 경계 확인·보정 → 적용.

- 사진 준비 실패: 사유 표시, 재시도, 촬영 화면으로 돌아가기.
- 자동 경계 추출 실패: 재시도 또는 준비된 사진에서 직접 영역 지정.
- 사진 표시 실패: 보정 적용을 중단하고 사진 준비부터 재시도.
- 중복 실행 방지, 화면을 떠난 뒤 도착한 응답 무시.
- 사진 준비 30초, 자동 영역 요청 120초의 응답 대기 한도.
- 3개 미만 꼭짓점·교차 경계·너무 작은 영역·미완성 영역의 적용 차단.
- 저장된 보정 제거와 촬영 선택 초기화 지원.

## 데이터와 좌표

regionDrafts 항목은 schemaVersion, imageIndex, imageFingerprint, imageWidth, imageHeight,
coordinateSpace, foodPolygons, source, reviewed, volumeValidated를 포함한다.

- AR 원본에서 내보낸 analysis.jpg: cpu_image_normalized. metadata·depth·confidence의 SHA256인 frameFingerprint를 포함한다.
- 일반 촬영·갤러리: display_image_normalized. 원본 AR 깊이에 적용할 때는 좌표 변환 검증이 필요하다.
- 0~1 정규화 좌표이며 화면의 여백 대신 사진 영역 내부를 기준으로 계산한다.
- 다른 지문·크기·좌표계의 자동 결과와 이전 보정값을 현재 사진에 섞지 않는다.
- 모델 출력에 유효하지 않은 좌표가 들어오면 실패 상태로 전환한다.

서버는 사진 인덱스·지문 형식·크기·좌표 범위·자료 크기를 검사하여 저장한다.
volumeValidated는 false로 고정하며 클라이언트의 임의 중량 필드는 저장 대상에서 제외한다.
CaptureEvidence.normalizeForStorage는 경계를 저장하고, 분석 작업의 기존 normalize는 AI 입력에서 경계를 제외한다.
이는 경계 보정만으로 실측 기반 중량이 확보됐다고 취급하는 것을 방지한다.
경계 자료는 식단의 capture_info에 포함되어 식단 삭제 수명주기를 따른다.

## 검증과 산출물

- Flutter 전체 테스트 48개 통과 후, 최종 변경된 영역 상태·화면 테스트 9개 재검증 통과. 신규 화면 테스트 2개를 포함한 고유 테스트 총 50개.
- Flutter 정적 검사 지적 사항 0건.
- 서버 전체 테스트 51개 통과, 최종 촬영 정보·경계 저장 관련 테스트 재검증 통과.
- Android debug APK 빌드 성공: mobile/build/app/outputs/flutter-apk/app-debug.apk
- 서버 실행 파일: backend/target/foodify-backend-0.0.1-SNAPSHOT.jar
- S23의 실제 터치 좌표·사진 방향·기기 성능 검증은 실기기 연결 후 수행한다.

새 APK와 새 서버 실행 파일을 함께 적용해야 보정 자료의 서버 보관까지 연결된다.
자동 분할 모델의 Android 실행, 접시 기준면 편집, AR 부피·중량 앱 계산은 별도 후속 작업이다.
