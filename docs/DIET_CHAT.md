# 기록 기반 식단 피드백 챗봇 (2026-10-08)

홈의 식단 피드백 챗봇 → 질문 입력 → 최신 기록 조회 및 대화 맥락 전달 → 답변·참고 기간 표시 → 후속 질문.

- 모델: gpt-4o-mini, Responses API, store:false 유지. Foodify 서버가 대화 상태를 관리하고 사용자/assistant 역할을 구분해 전달한다.
- 매 질문마다 한국 시간의 오늘·최근 7일 전체 완료 식단 영양 합계와 목표 대비 차이/비율을 조회한다. 미완료 식단 수와 누락 가능성을 함께 제공한다.
- 음식 상세는 최근 30끼, 끼니당 10개 음식까지. 이름과 영양값만 포함하며 사진·AR 자료·추정 중량은 챗봇에 재전송하지 않는다.
- 최근 완료 대화 10쌍을 모델에 전달. 화면은 최근 50개 질문/답변 쌍을 복원한다. 범위 밖 기록은 추측하지 않도록 안내한다.
- 서버가 기간·기준 시각·미완료 수를 답변에 첨부한다. 과거 답변은 당시 기준이며 변경된 식단은 다음 질문에 반영된다.
- 질문은 최대 2,000자. 동일 requestKey 재전송은 완료 결과를 재사용하며, 회원당 동시 생성 1건만 허용한다. 실패한 질문은 같은 키로 재시도한다. 3분 지난 처리 중 요청은 중단 상태로 복구한다.
- V5 chat_turns: 회원, 요청 키, 질문, 답변, 상태, 오류, 당시 근거 JSON, 생성/수정 시각. 대화 삭제 및 계정 삭제 연동. 생성 중 삭제는 완료 후 수행한다.
- AI 전송 동의 v2-chat에서 채팅 내용과 식단 상세 전송·보관을 추가 고지하고 재동의를 받는다. 기존 시험 운영 안내의 계약/국가 확정 과제는 유지한다.
- 입력 질문과 자료 속 문구는 사용자 데이터로 취급한다. 식생활 참고 범위를 지키며 의료적 판단은 전문 상담으로 안내한다.

API: GET /api/v1/chat (최근 대화), POST /api/v1/chat ({requestKey,message}), DELETE /api/v1/chat (현재 회원 대화 삭제).
구형 /feedback API는 호환용으로 유지하고 앱의 피드백 진입은 챗봇으로 통합한다.

검증: 모델 응답 모의 테스트와 로컬 가짜 HTTP 응답으로 역할·맥락·store:false 확인. 실제 유료 응답의 영양 상담 품질은 별도 평가 대상이다.
