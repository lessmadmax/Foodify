# AI 그릇 판별과 AR 기준면 연결 구현

## 목적과 상태

그릇 종류·테두리를 AI가 내부 판별하고 임시 내부 깊이를 AR 기준면·면적·높이 계산에 연결하였다. 식단 AR 화면에는 그릇 선택·깊이 표시·접시 영역 지정 버튼을 제공하지 않는다. 기존 음식 윤곽 확인은 유지한다. 자동 테스트로 연결을 확인했으며 실제 중량 정확도 개선은 아직 검증 전이다.

## 처리 흐름

1. 음식 윤곽 확인 후 사진·음식명을 인증·AI 동의가 필요한 `POST /api/v1/ar/vessel`로 전송한다. 촬영당 한 번 시도하고 재계산에는 캐시를 쓰며 새 촬영에서 초기화한다.
2. `OpenAiClient.locateVessel`은 종류, high/medium/low 자기 보고 확신, 정규화 테두리 점을 요청한다. 깊이·두께·중량 수치는 생성시키지 않는다. high는 보정된 정확도 확률이 아니다.
3. 서버 `VesselReference`와 기기 `ArVessel`의 고정 깊이는 밥그릇 5.8cm, 평면 접시 0.8cm, 국그릇 3.0cm, 깊은 접시 3.5cm다. 인터넷 개별 제품·제작 사례 기반 임시값이며 실제 그릇 실측이 아니다.
4. high 판별에서만 테두리 주변 AR 깊이(신뢰도 128 이상), 부족하면 특징점을 모은다. 점 수·테두리 분포·평면 오차·인라이어·기울기·다각형 정상 여부와 음식 포함 여부를 검사한다.
5. 카메라 쪽 단위 법선의 테두리 평면 `n·X+d=0`에서 바닥을 `n·X+(d+기본 깊이)=0`으로 근사한다. 중심 광선과 바닥의 교점으로 축척·면적을 다시 계산하고, 음식 점에서 이 바닥까지의 거리를 평균 높이로 쓴다. 내부 단위는 mm이며 입력 깊이는 cm에서 변환한다.
6. 음식 깊이 20점·관측률 30% 우선, 없으면 12개 이상·여러 영상 셀에 분포한 음식 특징점을 사용한다. 높이를 얻지 못하면 기존 AI 높이 대체 경로를 이용하되 기기 측정이라고 기록하지 않는다. 서버는 보정된 면적×높이×분류 밀도로 중량을 재계산한다.
7. 기존 식단 JSON의 `vesselReference`에 종류·적용 여부·출처·기본 깊이·테두리/바닥 거리·테두리 점·표본 수·평면 오차·근사 모델을 저장한다. `qualityHold=true`, `volumeValidated=false`를 강제한다. DB 스키마 변경은 없다.

## 실패 처리와 한계

판별 API 오류·구버전 서버·동의 부족·unknown·불확실 판별은 그릇 보정을 적용하지 않고 기존 측정 경로를 사용하며 미적용 근거를 남긴다. 사용자에게 그릇 선택을 요구하지 않는다. high 판별을 받았지만 테두리 지지점·평면 품질이 부족하거나 영역이 틀리면 계산을 중단하고 일반적인 재촬영 안내를 한다. 품질이 나쁜 테두리를 배경으로 대체해 보정하지 않는다.

실제 AI 판별이 맞는지는 실측 검증이 필요하다. 배경이 우연히 좋은 평면으로 검출되는 가능성까지 기하 검사로 완전히 배제할 수는 없다. 모든 종류의 바닥을 평면으로 근사하므로 곡면 밥그릇·국그릇에 중앙 최대 깊이를 일괄 적용하면 부피가 과대 추정될 수 있다. 실제 그릇 치수, AR·특징점 편향, 음식 윤곽·밀도 오차도 남아 있다. 기존 깊이 적분 부피는 보정 결과가 아닌 참고값으로 유지한다.

촬영당 그릇 판별 API 최대 1회가 추가된다. 높이 대체가 필요하면 기존 최대 3회 높이 질문도 발생할 수 있다. 이번 개발 테스트에서는 로컬 가짜 API 응답을 사용했고 외부 유료 호출은 하지 않았다.

## 검증

- 서버 전체 및 후속 저장 테스트 합계 78개, 실패 0. 판별 요청·고정값·미검증 상태·인증/동의·식단 저장을 확인했다.
- Kotlin `ArVesselTest` 5개, `ArVolumeTest` 25개, `ArFusionTest` 6개 통과. 테두리 30cm+기본 깊이 3cm−음식 표면 31cm=높이 2cm, 깊이 부족·영역 이탈·불확실/비정상 윤곽을 확인했다.
- Flutter 전체 59개 통과. 판별→네이티브 전달, 촬영당 캐시와 재촬영 초기화, API 실패 처리, 그릇 UI 비노출을 확인했다. 변경 파일 정적 분석 오류 없음.
- 실제 S23 설치·저울 비교는 별도다. 개발 시점 ADB 연결 기기는 없었다. 이 자동 테스트 결과를 정확도 향상 근거로 쓰지 않는다.
