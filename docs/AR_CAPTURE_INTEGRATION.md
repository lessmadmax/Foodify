# AR 보조 촬영·갤러리 분석 (2026-10-05)

## 사용 방법

- 갤러리: 촬영 화면 → 갤러리에서 선택 → 최대 3장 → 전송 동의 → 자동 저장하고 분석.
- 사진 촬영: 선택된 사진이 없는 상태에서 사진 촬영 → 지원 기기에서 자동 AR 진입 → 사진 촬영 · 5초 → 저장 후 자동 복귀 → 대표 사진과 깊이 요약 확인 → 전송 동의 → 분석.
- 촬영 방식을 바꾸려면 선택 초기화를 누른다. AR 사진은 다른 카메라·갤러리 사진과 섞지 않는다.
- AR 사용이 어렵거나 유효 깊이를 확보하지 못하면 안내 후 일반 카메라로 전환한다. AR 화면에서도 일반 사진 촬영으로 전환할 수 있다. 취소는 분석 화면으로 돌아간다.
- 진단 경로: 홈 우측 메뉴 → 설정 → 개발자 메뉴 → AR 깊이 진단 · 실험. 촬영 화면에는 사진 촬영·갤러리에서 선택 두 입력 버튼만 표시한다.

## 구현 범위

Android가 저장한 YUV를 JPEG로 변환하고 동일 프레임의 깊이 통계·내부 파라미터를 반환한다.
최대 10개 후보 중 추적 정상, 깊이 시간차 100ms 이하, 카메라 시간차 50ms 이하,
신뢰도 128 이상 깊이 픽셀 비율 5% 이상인 프레임에서 가장 높은 유효 비율의 대표 1장을 선택한다.
이 기준은 초기 필터이며 중량 정확도를 보장하는 기준과 구분한다.

서버에 전달하는 값: 장면 깊이 중앙값(mm), 유효 신뢰도 픽셀 비율, 시간차,
원본 사진 크기, 초점거리·주점(원본 픽셀 좌표). 서버 사진 리사이징 시 원본 크기 기준 보정값이라는 점을 유지한다.
원본 깊이 지도·점군은 로컬 실험 자료로 남는다. 서버와 OpenAI에는 대표 사진과 요약만 전송한다.
서버는 허용 필드·범위·사진 수를 검증하고 volumeValidated=false를 유지한다.
capture_info는 식단에 저장되며 재분석에도 사용한다. 앱 전송 대기 파일에도 보존해 재전송한다.

현재 결과는 **AR 장면 거리 요약을 참고한 LLM 중량 추정**이다.
음식 영역의 깊이 분할, 받침면 높이 차이, 부피 적분, 음식별 밀도 기반 중량 계산은 후속 구현이다.
장면 중앙값은 음식 높이가 아니며 배경·접시 영향을 받는다. 사진만으로 추정 근거가 부족하면 중량은 null로 남고 사용자 입력을 안내한다.
갤러리 사진은 별도 깊이 정보 없이 사진 기반 참고 추정을 사용한다.

## 검증

- 서버: AR 데이터 검증 6개, 가짜 API 서버를 사용한 측정 근거 전달·null 중량 유지 1개 추가.
- Flutter: AR 반환·취소 2개, 촬영·갤러리·AR UI 1개 추가.
- 실제 API 유료 호출, 갤러리 사진 업로드, AR 촬영 내보내기 및 중량 정확도 실측은 별도 실기기 확인 대상.
- S23 AR 정상 동작은 사용자 확인을 받았으며, 이번 신규 대표 사진 내보내기 흐름과 구분한다.

요청 형식 참고: [OpenAI 공식 이미지 입력 문서](https://developers.openai.com/api/docs/guides/images-vision).
