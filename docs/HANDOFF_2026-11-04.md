# Foodify 작업 인계 (2026-11-04)

claude.ai 세션에서 진행한 작업을 Windows에서 실행하는 Claude Code 세션으로 넘기기 위한 문서다. 진척 전체는 [PROJECT_CHECKLIST.md](PROJECT_CHECKLIST.md)를 기준으로 하고, 이 문서는 11월 4일 결정·변경·남은 일과 실행 환경 주의점을 정리한다.

## 1. 확정한 분석 구조

```
인식:   분류 모델(한식 추가 학습) → 점수 낮거나 목록 밖이면 LLM(API) → 사용자 확인
중량:   AR 부피 × 음식별 계수 → 부족하면 LLM(API) 추정, 범위 표시 → 사용자 수정
DB:     검색 규칙 + 사용자 선택 (LLM 선택은 보조)
피드백: Gemma (S23 기기 안) ← S23 속도 확인 후 적용
챗봇:   Gemma (기기 안), 실패 시 API ← 비교 평가 후 결정
```

현재 코드는 아직 이 구조가 아니다. 지금은 Food-101 후보를 참고로 넘기고 OpenAI(gpt-4o-mini)가 음식명·중량을 결정하며, AR 부피 계산은 연구 화면에만 있다. 체크리스트의 **M. 분석 구조 개편(M01~M11)**이 전환 작업이다.

## 4. 바로 이어서 할 일

1. **서버 재시작** (CaptureEvidence 변경 반영).
2. **S23 피드백 생성 시간 측정**
   - `flutter test test/local_model_screen_test.dart` → `flutter build apk --debug --dart-define=API_BASE_URL=http://127.0.0.1:8080/api/v1` → `adb install -r` (`scripts/build_install_s23.bat`과 동일). 컴파일 오류가 나면 위 세 파일부터 확인.
   - S23: 설정 → 개발자 메뉴 → 기기 내 음식 분석 · Gemma → 피드백 생성 시간 측정 → 결과 복사.
   - 판단 기준(제안): 재사용 엔진 기준 10~15초 이내면 기기 안 Gemma 피드백 채택(M09). 응답 길이·필드명 노출은 프롬프트("필드명 없이 2~3문장")로 개선 시도.
3. **(선택) 피드백 비교 재실행**: `python scripts/eval_feedback_llm.py scenarios|gemma gpu|api|score`. 7일 시나리오 확인과 PC GPU 속도.
4. 이후 체크리스트 M03(음식명 고정 API 재실험) → M11(AR 촬영 규칙 안내와 재수집) → M04~M07 순서 권장. 1순위 실기기 흐름 확인(E08, B05, C06, D01, G03~G05, H01)은 병행.
