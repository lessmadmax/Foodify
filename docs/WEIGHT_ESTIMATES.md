# 중량 추정·음식 검색·자동 완료 (2026-10-07)

사진 분석 응답은 기존 grams(대표 중량)에 weightEstimate를 추가한다.

```json
{
  "name": "햄버거",
  "grams": 220,
  "weightEstimate": {
    "lowerGrams": 170,
    "upperGrams": 280,
    "assumptions": ["보통 크기 햄버거 1개로 가정"]
  },
  "uncertainty": "패티 두께와 실제 크기를 확인하기 어려움"
}
```

위 숫자는 형식 예시이며 실제 분석 결과가 아니다. 예상 범위는 사진 기반의 참고 범위이고 통계적 신뢰구간이 아니다.
서버는 0 < 하한 <= 대표값 <= 상한 <= 10000g, 가정 1~5개를 검증한다.
판단 근거가 매우 부족하면 세 중량값 모두 null과 구체적 이유를 허용한다.
범위·가정은 식단 items JSON에 저장한다. 동일 음식명·중량의 유일한 기존 항목은 저장 후에도 근거를 유지한다.
음식명·중량을 수정하면 이전 추정 근거를 해제하고 영양값을 다시 계산한다. 오래된 기록은 재분석해야 새 범위가 생긴다.
프롬프트 버전: v3-weight-range. 모델: gpt-4o-mini 유지.

검색은 공백·밑줄·하이픈을 정리한 전체 음식명부터 시작한다.
버거는 불고기/치즈/치킨 유형을 우선하고 햄버거로 확장한다.
예: 소고기 치즈 햄버거 → 소고기치즈햄버거 → 치즈버거 → 햄버거.
첫 후보가 있는 단계에서 검색을 멈춘다. 유사 유형 후보에는 searchFallback과 searchTerm을 표시한다.
정확한 제품과 유사 후보는 구분되며 자동 DB 후보 선택이 불확실하면 보정 대상으로 남는다.

음식 확인 체크박스를 제거했다. 대표 중량과 DB 기준·필수 영양값이 모두 있으면 자동 COMPLETE 처리한다.
식단 전체 음식이 COMPLETE일 때 일간/주간 합계에 반영한다. null 중량, DB 미연결, 영양값 누락은 INCOMPLETE로 유지한다.
이전의 체크 대기 기록은 수정 저장으로 재계산하거나 재분석할 수 있다. 기존 기록을 일괄 변경하지 않는다.
외부 AI 전송 동의 체크박스는 개인정보 처리 동의이므로 유지한다.
