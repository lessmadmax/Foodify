# S23 AR 중량 측정·전자저울 자료 수집

2026-11-02. PC에서 실행하던 수동 영역 기반 부피 계산과 음식별 실측 보정·평가 기능을 Android로 옮겼다. S23의 **AR 중량 측정** 화면에서 서버·로그인 없이 실행한다. 기존 식단 분석·챗봇은 각자의 서버 연결을 사용한다.

## 사용 순서

1. 로그인 화면의 **AR 중량 측정 · 오프라인**, 또는 홈의 **AR 중량 측정 · 실측 기록**을 연다.
2. 평평한 접시를 전자저울에 올려 영점을 맞추고 음식만의 중량을 잰다. 초기 실험은 밥처럼 단순한 형태의 한 종류 음식으로 시작한다.
3. **AR 촬영**을 누른다. 밝은 곳에서 접시와 음식을 위쪽에서 비추고 5초 동안 천천히 옆으로 움직인다. 실제 음식·접시 기준면의 깊이 품질은 계산 단계에서 확인한다.
4. 저장된 촬영과 프레임을 고른다. 자동 대표 사진 선택이 실패해도 저장된 원본 프레임을 열 수 있다.
5. **음식 영역 지정**에서 음식 테두리를 눌러 다각형을 만들고 **영역 완성 → 보정 적용**을 누른다. 한 기록에는 같은 음식 한 종류의 영역을 지정한다.
6. **접시 기준면 지정**에서 음식을 포함한 접시 영역을 지정한다. 앱이 음식 영역을 자동 제외하고 남은 접시 표면에서 기준면을 구한다. 평평한 안쪽을 중심으로 지정하고 테두리·곡면·식탁을 제외하면 계산에 도움이 된다. 남은 평면이 불충분하면 사유가 표시된다.
7. 음식명, 제공량 그룹, 자료 용도, 전자저울 중량(g)을 입력한다. 음식명의 표기를 통일한다.
8. **부피 계산**으로 결과와 품질 사유를 보고 **실측 기록 저장**을 누른다. 영역 지정 전이나 품질 보류 상태에서도 저울값을 저장할 수 있다.
9. 음식량을 바꾸지 않고 반복 촬영하면 같은 제공량 그룹을 사용한다. 양을 바꾸면 새 그룹으로 기록한다.
10. 유효한 보정 제공량 3그룹 이상을 모은 뒤 **현재 음식의 환산식 생성**을 누른다. 이후 해당 음식의 유효 부피에 환산 중량이 표시된다.
11. 보정에 쓰지 않은 새로운 제공량을 **평가용**으로 저장하고 **현재 음식의 평가 결과**를 확인한다.
12. **모든 실측 자료 ZIP 내보내기**로 휴대폰의 원하는 위치에 백업한다. 앱 삭제 전에 내보낸다.

## 기록 예시

| 음식명 | 제공량 그룹 | 자료 용도 | 저울값 | 촬영 |
|---|---|---|---:|---|
| 흰쌀밥 | 밥-A | 보정용 | 실제 측정값 | 동일 제공량으로 2회 |
| 흰쌀밥 | 밥-B | 보정용 | 실제 측정값 | 양을 바꿔 2회 |
| 흰쌀밥 | 밥-C | 보정용 | 실제 측정값 | 양을 바꿔 2회 |
| 흰쌀밥 | 밥-D | 평가용 | 실제 측정값 | 새로운 양으로 2회 |

그룹의 이름에 중량을 넣어도 되지만, 정확한 저울값은 중량 입력란에 별도로 기록한다. 같은 음식의 같은 제공량 그룹을 보정·평가 양쪽에 저장하면 차단한다. 충분한 평가는 음식별 10개 이상의 다양한 제공량을 권장하며, 3개는 환산식 생성의 최소 조건이다.

## S23 내부 계산

- 깊이 픽셀을 기록된 좌표 변환·카메라 내부 파라미터로 3차원 점으로 변환한다.
- `기준면 후보 = 지정한 접시 영역 − 음식 영역`으로 음식 부분을 제외한다. 후보의 유효 깊이에서 RANSAC과 직교 평면 적합으로 받침면을 구한다. 평면에 맞지 않는 점은 적합 과정에서 제외하며, 평면 내점 비율이 기준에 미달하면 보류한다.
- 음식 영역과 기준면의 높이 차이를 깊이 격자의 삼각형 면적에 적분해 관측 부피(mL)를 구한다.
- 부피 계산에는 저울값을 넣지 않는다. 저울값은 음식별 환산식 보정과 독립 평가의 정답 자료다.
- 보정용 자료를 제공량 그룹별 중앙값으로 묶고, 원점을 지나는 선형식 `중량(g) = 부피(mL) × 환산밀도(g/mL)`를 적합한다.
- 평가용 그룹에서 평균 절대오차, 상대오차 중앙값, 유효 결과 확보율을 산출한다. 반복 촬영 횟수가 많은 그룹이 평가를 지배하지 않도록 그룹 단위로 집계한다.
- 보정에 사용한 기록을 수정·삭제하면 해당 환산식을 최신 자료로 다시 생성하도록 안내한다.

## 품질 보류와 한계

카메라 추적 실패, 깊이·신뢰도 시각 불일치, 깊이/신뢰도 지연 100ms 초과, 사진 지연 50ms 초과, 상단 촬영 기울기 30도 초과, 기준면 잔차 3mm 초과, 음식 유효 깊이 80% 미만, 적분 가능한 삼각형 비율 80% 미만 등의 경우 계산을 보류한다. 기준면에는 유효 점 20개 이상과 80% 이상의 평면 내점이 필요하다.

보류된 관측 부피와 사유는 저장하지만 중량 환산에 사용하는 유효 부피는 비워 둔다. 미확보 깊이를 임의로 채워 결과를 만들지 않는다. 실제 음식의 중량 정확도는 전자저울 자료로 확인해야 하며 `volumeValidated`는 아직 false다.

이번 Android 이식 범위는 **수동 음식·접시 영역 지정, 부피 계산, 실측 기록, 환산식, 평가, 내보내기**다. 자동 음식 마스크 추출기(MobileSAM)는 PC 실험 경로에 있으며 Android 추론 실행기 연동은 후속 작업이다. 초기 실측은 영역을 직접 지정하여 깊이·부피 오차와 영역 인식 오차를 구분한다. 관측한 윗면과 평평한 받침면 사이를 음식으로 적분하는 방식이므로 그릇·접시 곡면, 가려진 음식, 내부 빈 공간·공극은 별도 오차 요인이다. 음식 종류와 조리 상태가 바뀌면 같은 환산밀도의 적용 가능성을 다시 평가한다.

일반 식단 화면의 중량·영양 계산은 기존 분석 경로를 사용한다. 연구 화면의 실험값은 별도 자료로 관리하고, 실측 검증 후 일반 촬영 흐름에 적용한다.

## 저장·내보내기 구조

- `files/ar-diagnostics/<촬영 UUID>/frame-XX/`: 사진, 깊이 u16le, 신뢰도 u8, YUV, 촬영 메타데이터.
- `files/ar-research/records/<기록 UUID>.json`: 음식명, 제공량 그룹, 보정/평가 용도, 저울값, 영역 좌표·사진/프레임 지문, 계산 결과·품질 사유.
- `files/ar-research/models/<음식명 SHA256>.json`: 음식별 환산식과 보정 자료 출처·지문.
- ZIP: `manifest.json`, `records/`, `sessions/<촬영 UUID>/frame-XX/`, `calibrations/`.
- 기록의 `frameRelativePath`는 ZIP의 `sessions/` 아래 경로에 대응한다. 휴대폰 절대경로와 별도로 보존한다.
- 동일 프레임·음식·그룹·용도의 재저장은 기존 기록을 갱신한다. 기록 목록에서 재편집·삭제할 수 있다. 기록 삭제 시 촬영 원본은 보존한다.
- 촬영 원본 저장 한도는 1GiB, 단일 ZIP은 원본 합계 500MiB 이하, 최대 500기록이다. 대량 수집 전 여유 공간을 확인한다.

- 정적 검사와 debug APK 빌드 통과. S23(SM-S911N)에 기존 데이터 유지 방식으로 설치했다.

- Android의 `/data/user/0`와 `/data/data` 경로 차이로 기록 재열기 시 선택 항목이 맞지 않는 오류를 실기기에서 발견해 정규 경로로 수정하고 회귀 테스트·기기 재확인을 완료했다.
- 합성 입체 365.5125mL 복원과 기울어진 평면 적합을 확인했다. 합성 시험 통과는 실제 음식의 정확도 보장을 뜻하지 않는다.

## 2026-11-04 영역 겹침 처리 개선

Android와 PC 계산을 v2로 변경했다. 접시·음식 영역이 겹쳐도 음식 부분을 자동 제외해 계산한다. 결과에는 제외된 음식 픽셀 수, 남은 기준면 후보 수, 유효 기준면 픽셀 수를 기록한다. 접시 영역에서 음식 부분을 뺀 뒤 남는 표면이 없거나 깊이가 부족하면 구체적인 사유를 표시한다.

이전 기록은 연구 화면을 열면 새 알고리즘으로 자동 재계산한다. 음식명·그룹·원래 저장 시각·저울값·영역·사진은 유지하고 계산 결과와 재계산 시각만 갱신한다. 원래 기록은 `files/ar-research/backups/<UUID>-v1.json`에 보관하며 ZIP의 `previous-records/`에도 포함한다. 깊이 수집·시각 정합 문제는 별도 개선 대상이다.

개선 검증: Android 25개(영역 전체·부분 겹침·차집합 후 기준면 없음 포함), PC 부피 14개·자동 마스크 7개, 관련 Flutter 화면 4개 테스트 및 변경 화면 정적 검사 통과. 기존 6개 쿠키·밥 기록의 PC 재계산에서 겹침 오류가 해소되었고 유효 음식 깊이 부족·기준면 부족/불안정으로 보류됨을 확인했다.

S23 반영 확인: 수정 APK 설치 후 연구 화면에서 기존 쿠키 3개·밥 3개 기록을 v2로 자동 재계산했다. 6개 기록 모두 겹침 오류가 해소되었으며 원래 저울값·영역·촬영 경로·저장 시각이 유지되고 원본 백업 6개가 생성됐음을 설치 전후 비교로 확인했다. 음식 깊이 부족·시각 불일치·기준면 부족/불안정으로 부피는 계속 보류 상태다.

## v3 깊이 처리 개선

[깊이 재투영·프레임 결합 개선](AR_DEPTH_IMPROVEMENT_2026-11-04.md)을 적용했다. 기존 100ms 깊이 시각 차이·완전 동일 시각 조건은 최신 규칙을 우선한다. 연구 화면은 같은 세션 프레임의 실측 깊이를 카메라 자세로 정렬해 결합하고, 새 촬영은 일반 Depth도 비교용으로 함께 보관한다. 사진·깊이·신뢰도 대응 근거와 유효 음식 관측률을 따로 기록한다.
